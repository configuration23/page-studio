# Справочник портала: формат

Статус: **сделано** для подсказки у элемента. Страница «API» — отдельным шагом.

## Зачем

Вопросы, которые возникают при первом подключении — какой токен, куда уходит
событие, как записать картинку, почему 401 — повторяются у каждого. Справка должна
отвечать на них **внутри админки**, а не только в `docs/BACKEND.md`.

## Один источник

`src/help.ts` — записи по видам элементов. Из них собираются:

- блок «Справка» в инспекторе у выбранного элемента (заменил прежнюю подсказку «? что это и как заполнять» и блок «Методы»);
- страница «API» в админке (`/admin/api`) — весь контракт целиком.

Тест проверяет, что у каждого вида из `KINDS` есть запись и что лишних записей нет.
Методы и их HTTP-вызовы **генерируются** из модели (`methodsOf`), чтобы справка не
расходилась с кодом.

## Что видит админ у элемента

1. **Что это** — одно предложение.
2. **Свойства** — таблица: название, значения, по умолчанию.
3. **Методы** — таблица: метод, что делает, вызов.
4. **Что уходит в событии** — пример JSON (если у вида есть события).
5. **Как записать значение** — `curl` с реальными `slug` и `id` этой страницы.
6. **Частые ошибки** — 401, 415, 400 `sid` и что делать.

## Пример: как это будет выглядеть для «Текста»

```
Текст — блок данных

Блок текста: заголовок, пояснение, длинная инструкция. Длинный текст
прокручивается внутри блока. Пользователь его не редактирует.

Свойства
  данные      многострочный текст           —
  обмен       включён / выключен            выключен
  формат      обычный текст / маркдаун      обычный текст
  выравн.     слева / по центру / справа    слева

Методы                       (появляются только с включённым обменом)
  clipart.doc                прочитать     GET  /api/v1/forms/clipart/values/doc
  clipart.post_doc           записать      POST /api/v1/forms/clipart/values/doc

Событий у текста нет.

Как записать
  curl -X POST "http://192.168.1.86:3000/api/v1/forms/clipart/values/doc?sid=<sid>" \
    -H "Authorization: Bearer <PORTAL_TOKEN>" \
    -H "Content-Type: application/json" \
    -d '{"value": "текст до 20 000 символов"}'

Частые ошибки
  401  не тот токен: для записи значений нужен PORTAL_TOKEN, не токен API
  400  не передан sid или текст длиннее 20 000 символов
```

## Что видит админ на странице «API»

- **Авторизация**: `PORTAL_TOKEN` (запись значений) и токены админского API — таблица
  «кто и куда».
- **Эндпоинты**: страницы, значения, события, состояние страницы, картинки, админка,
  токены, цели — с методами и назначением.
- **По видам элементов**: те же блоки, что в инспекторе, только все сразу.
- Примеры — с реальным адресом портала (он известен серверу), кнопки «копировать».

## Правило для новых элементов и методов

Новый вид элемента или новый метод — это изменение контракта. В том же коммите:

1. запись в `src/help.ts`: что это, свойства, события, пример записи, ошибки;
2. методы и вызовы появятся в справке автоматически — руками не дублируем;
3. `docs/BACKEND.md` — если появился новый вызов с стороны бэкенда;
4. `CHANGELOG.md` — строка об изменении;
5. `pnpm test` — проверяет, что у каждого вида есть справка.

Без записи в `src/help.ts` новый вид не проходит проверку — так справка не отстаёт от
кода.
