# Идеи после первого опыта

Появились, когда портал уже работал с настоящим n8n. Всё это — **нужно решение**:
сначала договариваемся о поведении, потом код.

## 1. [x] Событие при открытии страницы

**Сделано:** элемент «Открытие» (`onload`), метод `page.on_open_<id>`, событие уходит
из браузера при каждой загрузке страницы. В дизайнере виден рамкой, на странице — нет.

**Что:** невидимый элемент-триггер, который при загрузке страницы шлёт событие
бэкенду — например `page.on_open_<id>` с тем же телом, что и кнопка.

**Зачем:** страница-дашборд: открыл — фронт сразу спросил «как дела» у нескольких
бэкендов, а те написали статусы, и страница обновилась по SSE.

**Решить:**
- когда срабатывает: один раз за сессию или при каждом открытии (перезагрузка, «назад»);
- включать ли в событие `values` (при первом открытии они пустые);
- нужен ли синхронный ответ: сейчас доставка fire-and-forget, дашборду это
  подходит — бэкенд пишет статусы отдельными вызовами.

## 2. [x] Статус в списке страниц

**Сделано:** «состояние страницы» без `sid`: `POST /api/v1/forms/<slug>/state`,
`GET /api/v1/pages`; в списке — точка и подпись, обновляются опросом раз в 15 с.

**Что:** на `/pages` у каждой страницы видно, работает ли её бэкенд, ещё до открытия.

**Решить, откуда берётся статус:**
- значение элемента «Статус» — не годится: оно у каждой сессии своё;
- **общее состояние страницы** (предлагаю): `POST /api/v1/forms/<slug>/state`
  без `sid`, хранится одно на страницу, показывается в списке, обновляется по SSE;
- опрос адреса цели — лишние запросы и утечка адресов.

## 3. [x] Вид списка страниц

**Что:** плитка, строки, компактный список.

**Сделано:** настройка портала в «Настройках страницы»: плитка, строки, компактный список; хранится в `data/settings.yaml`.

## 4. [x] Скрытие и активность

**Что было:** `hidden` у элемента, но без настройки в инспекторе; не было `disabled`,
скрытия страницы в списке и управления из бэкенда.

**Сделано:**
- статически: галочки «скрыт на странице» и «неактивен» в инспекторе; у страницы —
  «скрыть из списка» (по прямой ссылке открывается);
- динамически: `POST /api/v1/forms/<slug>/ui/<id>` с `{"hidden": true}` или
  `{"disabled": true}` — меняется **один** элемент, остальные не трогаются; `false`
  возвращает как было; страница обновляется по SSE;
- в дизайнере скрытый элемент не исчезает, а показывается пунктиром — иначе его не
  выделить и не вернуть.

**Решение по API:** один параметр на элемент (не отдельное состояние сессии) и адрес с `id`:
один запрос меняет один элемент, разные воркфлоу не перетирают друг друга.

## 5. Новые элементы

- **Спойлер** — `details`/`summary`, содержимое можно задать текстом или вложенными
  элементами (тут нужен ответ, поддерживаем ли вложенность).
- **Таблица** — колонки и строки, данные приходят от бэкенда (формат: массив объектов).
- **Встраивание** — iframe (drawio, карты, чужие виджеты). Главный вопрос —
  безопасность: `sandbox`, белый список источников, и как это сочетается с обещанием
  «работа без интернета». Обсудить отдельно.

## 6. Ноды для n8n

**Что:** пакет community nodes: триггер «событие страницы», действия «записать
статус», «положить картинку», «записать значение», «получить манифест».

**Решить:** публиковать в npm или ставить локально; кто отвечает за совместимость
версий n8n; авторизация — API-токены портала уже есть.

## 7. [x] Техническая подсказка вместо «на пальцах»

## 8. [x] Текст как блок данных (обсуждалось 25.11)

**Решено:** прокрутка внутри блока; только чтение (для ввода есть «Абзац»); значение
уходит в бэкенд снимком формы; лимит 20 000 символов; формат `text | markdown`
заложен в схему.

**Сделано:** поле «Данные» (многострочное, переносы сохраняются), галочка «обмен»
(методы `get`/`post`, до 20 000 символов), прокрутка длинного текста в дизайнере и на
странице.

**Сделано:** форматирование — минимальный маркдаун (жирный, курсив, списки, код,
ссылки `http(s)`; сырой HTML экранируется) и выравнивание `left | center | right`
(по умолчанию `left`), в инспекторе и на странице.
