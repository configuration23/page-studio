# ARCHITECTURE — page-studio

## 1. Центральные понятия

**Форма** (страница) — канвас фиксированной ширины и список элементов с координатами.
**Элемент** — ячейка с типом, именем и свойствами. Имя элемента *и есть* имя метода.
**Сессия** — посетитель (cookie `ps_sid`). Значения полей живут в сессии; картинки —
общие.

Форма хранится файлом `data/forms/<slug>.yaml` (YAML читает и JSON, поэтому дизайнер
этапа B сможет писать тот же формат).

```yaml
slug: generation
title: Генерация
canvas: { width: 960 }
elements:
  - id: prompt
    kind: memo
    x: 40
    y: 120
    w: 640
    h: 96
    label: Промпт
    props: { placeholder: "кот-астронавт", max: 800 }
```

## 2. Виды элементов и методы

| kind | Что это | `get` | событие | `post` |
|---|---|---|---|---|
| `label` | статичный текст | — | — | — |
| `edit` | строка | `form.id` | `on_change` | `form.post_id` |
| `memo` | многострочное | `form.id` | `on_change` | `form.post_id` |
| `combo` | выбор | `form.id` | `on_change` | `form.post_id` |
| `check` | флажок | `form.id` | `on_change` | `form.post_id` |
| `button` | кнопка | — | `on_click` | — |
| `image` | одна картинка | `form.id` | — | `form.post_id` |
| `gallery` | лента картинок | `form.id` | — | `form.post_id` |
| `list` | список строк | `form.id` | — | `form.post_id` |
| `status` | состояние | `form.id` | — | `form.post_id` |

Правило имён, одно на все виды:

```
<slug>.<id>              прочитать значение
<slug>.post_<id>         записать значение
<slug>.<event>_<id>      событие, например on_click_push
```

Для страницы `generation` с элементами `prompt`, `push`, `status`, `image`:

| Метод | Направление | Кто зовёт |
|---|---|---|
| `generation.prompt` | чтение | бэкенд: `GET .../values/prompt` |
| `generation.on_change_prompt` | событие | браузер → портал → бэкенд |
| `generation.on_click_push` | событие | браузер → портал → бэкенд |
| `generation.post_status` | запись | бэкенд: `POST .../values/status` |
| `generation.post_image` | запись | бэкенд: `POST .../values/image` (байты) |
| `generation.gallery` | чтение | бэкенд: `GET .../values/gallery` |

Переименование `id` ломает обвязку, поэтому старое имя сохраняется алиасом:
`aliases: { prompt: text }` — метод `generation.prompt` продолжает работать и ведёт
к элементу `text`. Алиас живёт, пока имя не займёт другой элемент.

## 3. API

```
GET  /p/<slug>                              страница для пользователя
GET  /api/v1/forms/<slug>/manifest          элементы и их методы
GET  /api/v1/forms/<slug>/values/<id>       {"value": ...}
POST /api/v1/forms/<slug>/values/<id>       запись: JSON или image/* байтами
POST /api/v1/forms/<slug>/events/<id>       браузер: нажатие/изменение
GET  /api/v1/forms/<slug>/stream            SSE: изменения состояния
GET  /media/<imageId>                       картинка из хранилища
GET  /api/v1/log                            последние вызовы (для админа)
```

Запись картинки: `POST .../values/image?sid=<sid>` с `Content-Type: image/png`
и телом-файлом. Портал сохраняет байты, кладёт в значение `{imageId}` и добавляет
запись в общую галерею.

## 4. Событие и снимок формы

Событие уходит в бэкенд одним запросом и несёт значения **всех** полей формы — чтобы
воркфлоу не делал отдельных `GET` и не читал устаревшее значение:

```json
{
  "page": "generation",
  "element": "push",
  "event": "on_click",
  "sid": "a1b2c3d4",
  "ts": "2026-11-22T01:20:00.000Z",
  "values": { "prompt": "кот-астронавт", "status": { "state": "idle" } }
}
```

Привязка «событие → вебхук» лежит в `data/bindings.yaml`, не в форме: URL вебхука —
секрет, форму можно экспортировать.

```yaml
- on: generation/on_click/push
  url: http://192.168.1.126:5678/webhook/gen-push
```

Отправка — fire-and-forget: таймаут 3 с, три попытки, результат в журнал. Портал не
ждёт бэкенд и не зависит от его ответа.

## 5. Состояние и живые обновления

- Значения — `Map<slug, Map<sid, Values>>` в памяти + снимок в `data/state/`.
- Снимки старше 30 дней удаляются при старте: сессии копятся с каждого браузера.
- Изменение → событие в SSE-канал этой пары (slug, sid); браузер обновляет DOM по
  `data-id`, без перезагрузки.
- SSE, а не опрос: одно соединение, переподключение из коробки, бэкенд не участвует.

## 6. Хранилище

```
data/forms/<slug>.yaml        опубликованные формы
data/forms/<slug>.draft.yaml  черновик (есть, пока не опубликован)
data/bindings.yaml            события → вебхуки
data/state/<slug>.<sid>.json  значения сессии
data/generations/             байты картинок + index.jsonl
data/logs/                    журнал вызовов (ротация)
```

Картинки в git не попадают (`.gitignore`): это личные данные.

## 7. Авторизация — три роли

| Кто | Как | Что закрывает |
|---|---|---|
| Админ | форма входа: логин и пароль из `ADMIN_USER` / `ADMIN_PASSWORD`, подписанная кука `ps_admin` на 7 дней | `/admin`, `/api/v1/admin/*`, предпросмотр черновика |
| Скрипты | HTTP Basic теми же логином и паролем | то же, удобно для curl |
| Пользователь | без входа, доступ по VPN/сети | страницы `/p/<slug>` |
| n8n | `Authorization: Bearer <PORTAL_TOKEN>` | запись значений и чтение манифеста |

Пароль админки проверяется в приложении: портал остаётся закрытым, даже если в
настройке nginx ошиблись. Без `ADMIN_PASSWORD` админка отвечает 503 — «выключена»,
а не «открыта».

Важно: страницы админки без входа **перенаправляют на форму** (303), а API отдаёт
`401` без заголовка `WWW-Authenticate`. Именно заголовок вызывал в браузере
модальный диалог пароля, из-за которого вкладка выглядела «думающей».

## 8. Этапы

**A. Контракт и рантайм** — модель, рендер, состояние, API, SSE, журнал, хранилище
картинок, демо-драйвер вместо бэкенда, Docker. Формы собираются правкой YAML.
Критерий: страница «Генерация» проходит полный цикл `нажал → статус → картинка`
без бэкенда.

**B. Дизайнер** — палитра, канвас с перетаскиванием и размером, инспектор
«Свойства / Методы», сохранение в YAML, Design/Run через «Открыть страницу».
Сделано: перетаскивание, размер, инспектор, сохранение с валидацией.
Осталось: отмена, черновик и публикация, создание страницы, алиасы имён.
Критерий этапа: страница собирается мышью с нуля.

## 9. Редактирование формы

`GET /api/v1/admin/forms` — список, `GET /api/v1/admin/forms/<slug>` — форма целиком,
`PUT /api/v1/admin/forms/<slug>` — сохранение черновика,
`POST /api/v1/admin/forms/<slug>/publish` — публикация.

Сохранение пишет `data/forms/<slug>.draft.yaml` и **не** меняет живую страницу.
Публикация переносит черновик в `<slug>.yaml`, обновляет карту в памяти и удаляет
черновик. Пользователи видят только опубликованное — как design-time и run-time
в Delphi. Черновик можно посмотреть по `/p/<slug>?draft=1`; на публичном хосте этот
адрес стоит закрыть тем же basic auth, что и `/admin`.

Файл пишется без значений по умолчанию, чтобы оставался читаемым.
`slug` менять нельзя: он входит в имена методов.

`id` элемента переименовывать можно: вместе с ним меняется имя метода. Духа защиты
нет — после переименования обвязку в бэкенде нужно поправить; алиасы старых имён в бэклоге.

Доступ к `/admin` и `/api/v1/admin/*` — на стороне nginx (basic auth). Своего входа
у портала нет.
