# Как участвовать

Проект личный, но правила простые и обязательные — они же спасают от «почти
готово, которое тянется три месяца».

## Ветки

- `main` — только рабочее состояние. Прямые коммиты в `main` запрещены.
- Задача — ветка `feat/<тема>`, `fix/<тема>` или `docs/<тема>` от `main`.
- Слияние в `main` — после зелёных проверок и просмотра изменений.

## Перед коммитом

```bash
pnpm typecheck        # типы
pnpm build            # сборка в dist
pnpm test             # 20 юнит-проверок
pnpm smoke            # 17 сквозных, нужны запущенные портал и драйвер
```

`pnpm smoke` гоняется локально: он поднимает реальные HTTP-запросы и требует
`pnpm start` и `pnpm demo` в соседних терминалах.

## Коммиты

- По-русски, в императиве: `админка: вход по паролю из конфига`.
- Один заход — один шаг: мелкая правка и новая функциональность — разные коммиты.
- Документация обновляется тем же коммитом, что и поведение. Расхождение кода
  и документа считается дефектом.
- Отложенное — только в `docs/BACKLOG.md`, без второго списка.

## Стиль

- TypeScript, ESM, импорты с `.js`; фронтенд — обычный JS без сборщика.
- Внешних CDN, шрифтов и трекеров нет: страницы должны открываться без интернета.
- В логах — идентификаторы, не данные пользователей.

## Что проверить перед PR

- [ ] `pnpm typecheck`, `pnpm build`, `pnpm test` зелёные
- [ ] изменение поведения описано в `README.md` или `docs/`
- [ ] в `docs/BACKLOG.md` нет дублей
- [ ] секреты не попали в git (`.env`, токены, адреса вебхуков)
