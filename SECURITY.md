# Безопасность

Портал рассчитан на личное использование: один админ, ограниченный круг
пользователей, домашняя сеть или VPN. Это не многопользовательская платформа.

## Как сообщить об уязвимости

Приватно: **GitHub → Security → Report a vulnerability**.
Публичный issue создавать не нужно — сначала исправим.

В сообщении достаточно: версия (коммит), шаги воспроизведения, что происходит
и что должно происходить.

## Что считается уязвимостью

- обход входа в админку (`/admin`, `/api/v1/admin/*`) или предпросмотра черновика;
- запись значений без `Authorization: Bearer <PORTAL_TOKEN>`;
- подмена чужой сессии (`sid`) и чтение чужих значений;
- XSS через значения, приходящие от бэкенда (метки, тексты, имена картинок);
- обход проверок при загрузке картинки: не-image тип, размер сверх лимита;
- выход за каталог данных (`path traversal`) через `id` или имя файла.

## Модель защиты

| Что | Как закрыто |
|---|---|
| Админка | HTTP Basic, логин и пароль из `ADMIN_USER` / `ADMIN_PASSWORD` |
| Запись значений | `Authorization: Bearer`, сравнение токена в постоянном времени |
| Черновик | тот же вход, что и в админку (`/p/<slug>?draft=1`) |
| Наружный доступ | приложение слушает `127.0.0.1`; снаружи — nginx с TLS |
| Значения на странице | экранируются при рендере и при обновлении через SSE |
| Картинки | только `image/*`, лимит `MAX_IMAGE_BYTES`, SVG отдаётся с `CSP: sandbox` |
| Логи | пишутся идентификаторы и статусы, не содержимое полей |

## Если что-то утекло

1. Сменить `ADMIN_PASSWORD` и `PORTAL_TOKEN`, перезапустить сервис.
2. Проверить `logs/calls.jsonl` на чужие вызовы.
3. Обновить привязки вебхуков в `data/bindings.yaml`, если известен адрес бэкенда.
4. Данные сессий и картинки лежат в `data/` — при сомнении удалить снимки сессий.
